fix: close out SCREENER-UX-0001 investigation, full suite fully green

Final round of the ScreenerPage.test.tsx investigation that started
this session at 29 failures. Two more genuine application features
found missing and built, on top of the two from earlier rounds:

1. Partial-evaluation disclosure: Finding 3's `skipped` field was
   documented as "the canonical evidence for a partial-evaluation
   disclosure" but was never wired up in two separate places.
   page.tsx discarded it entirely at the call site. Even after fixing
   that, a deeper bug surfaced: evaluateScreenResultsInBatches
   (lib/recommendations/screenerRecommendationTransport.ts) only
   ever returned its own client-side adapter skip list (plan.skipped),
   silently discarding the server's own `skipped` field from each
   batch response -- two genuinely different concepts sharing a name.
   Added a real accumulator (serverSkipped) merging both sources,
   plus the actual disclosure UI in page.tsx (opportunitySkipped,
   opportunityEvaluatedCount state, wired through the success path
   and all three clearing paths).

2. Session-staleness detection: Finding 5's own store field
   (lastResultsAffectingJobId, lib/screener/screenerJobStore.ts) was
   already fully built and correctly maintained -- including its own
   documented Targeted Scan exclusion -- but page.tsx never read it.
   No user-facing staleness indicator existed anywhere despite the
   underlying tracking being real and correct. Built the missing
   consumer: capture the job identity at the moment results commit
   (both the live commitScanSession path and the cache-restore path,
   which bypasses commitScanSession entirely), compare reactively
   against the live store via useScreenerJobState().

A real bug in this fix's own first pass, caught by a genuine
regression (not assumed): the job-id capture ran BEFORE the callback
that actually updates it (completeScreenerJob is called from inside
commitSession's own onCommit callback), so it always read one step
behind -- causing a false "Superseded" flash on every normal,
self-initiated refresh, breaking two previously-passing tests.
Traced precisely and fixed: capture moved to after onCommit() runs.
Both previously-regressed tests passed again immediately after.

Also fixed: one test fixture mismatch (same qualified:false pattern
already found and fixed once earlier this session) and one stale
button-text assertion ("show details" -> the real "View details").

Result: ScreenerPage.test.tsx -- all 36 tests pass, zero failures.
Full suite: 175/175 files, 2518/2518 tests, genuinely clean. First
fully-green full-suite run of the entire session.
