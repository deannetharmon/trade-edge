test: fix two real gaps in ScreenerPage.test.tsx's ranked-scan tests

Not app bugs -- the real app has two deliberate, already-shipped
safety correctives this test file never caught up to:

1. SCREENER-RESULTS-0001: useRankedScan.ts requires input.activeSymbols
   on a ranked-scan task to reconstruct a proper session. Without it,
   the app correctly fails closed (sets an error, never displays
   results) rather than bypassing accounting. 19 createTask calls in
   this file never passed it.
2. Same corrective: any symbol absent from rawScanCache is recorded
   as a genuine MARKET_DATA_REQUEST_FAILED, even when results has
   real, valid data for it -- a symbol only lands in rawScanCache
   after its own real chain/quote fetch succeeds. 18 of the same
   completeTask calls passed rawScanCache: [], silently discarding
   their own real results.

Both fixed with exact per-test symbol lists extracted directly from
each completeTask call's own results/makeLargeTransportResult calls,
not guessed.

IMPORTANT: this is a PARTIAL fix. A larger, separate, real issue
remains and is NOT addressed here -- a documented, already-shipped
UI redesign (SCREENER-UX-0001) replaced the old #ranked-opportunities
panel with BestOpportunitiesShortlist; that old element no longer
exists anywhere in the app. Most of this test file's remaining
failures reference the retired element and need a real rewrite
against the new component, not a small fix. That is intentionally
parked as its own, separate, larger ticket -- see conversation
history for full detail before starting it.

Net effect: 1 additional passing test, zero regressions. The file
itself remains in the known-failing baseline set.
