fix: real refresh-preservation bugs in ranked scan orchestration

Started as an investigation into failing SCREENER-UX-0001 tests.
Traced through real debug instrumentation to five genuine
application bugs, not test artifacts -- all in the Rank mode refresh
lifecycle (useRankedScan.ts / app/screener/page.tsx):

1. startRankedScan() called setResults([]) synchronously at refresh
   start, wiping prior valid results before the new scan's own
   results ever arrived. Removed -- results now naturally retains
   its prior value until the completion handler actually replaces
   it.

2. The results panel's render gate required !loading unconditionally,
   hiding the ENTIRE panel (not just refreshing content) during any
   refresh. Split into two cases: the full-screen spinner now only
   shows for a genuine first scan (nothing to show yet); a refresh
   with prior valid results gets its own smaller indicator inside
   the still-visible panel instead.

3. The recommendations effect cleared opportunityRecommendations the
   instant a session transitioned to 'running' (any refresh),
   including refreshes of the exact same session. Narrowed to
   preserve prior valid recommendations specifically while refreshing
   (never for a genuinely different/stale/PMCC session) -- does not
   weaken the real safety rule (never GENERATE new recommendations
   for a running session's own in-flight data), only avoids wiping
   already-valid prior ones prematurely.

4. opportunityError/opportunityState were being set correctly by the
   catch block this whole time but never rendered anywhere -- a
   genuinely missing UI element. Added a real role="alert" disclosure,
   shown alongside (not instead of) still-visible prior results.

5. A failed refresh's catch block unconditionally cleared
   opportunityRecommendations, wiping prior valid data even though
   only the NEW fetch failed. Now only clears when there was nothing
   valid to preserve in the first place.

All five verified individually via targeted debug instrumentation
(added, confirmed the real runtime state, then removed -- zero debug
code remains in the diff). Full-suite regression check clean: 174/175
other files, 2505/2521 other tests unaffected by these four
state-machine changes.

Supporting test-infrastructure fixes in the same file: a real element-
ID rename (#ranked-opportunities -> best-opportunities-shortlist
testid), corrected loading-state text, a removed-control cleanup, a
full BestOpportunitiesShortlist content-assertion rewrite against the
real component, a systemic session-gating fix (seedCompletedSession
helper closing a gap where kv.set('results', ...) alone stopped
satisfying a real completeness gate the redesign added -- 15 call
sites), smart refresh-vs-first-scan button targeting, and a test
fixture watchlist-scope correction.

Net: 29 failures -> 16 in this file. The remaining 16 are a separate,
fresh investigation -- not continued in this pass, per Alan's
checkpoint recommendation after four consecutive changes to the same
refresh state machine in one sitting.
