## 4. Canonical content-model location

`lib/help/optionsStrategyReference.ts`. Single source of truth for:
- The 8 `StrategyId`s and their full `StrategyReferenceEntry` records (all 22 required fields).
- The 6 `Goal`s and their strategy membership (`GOALS`), including per-goal outlook-label overrides (e.g., Bull Put Spread reads "Neutral to bullish" specifically under the neutral/range goal).
- `applicableGoals` on each strategy entry is **derived** from `GOALS` at module load (`buildStrategyReference()`), not hand-duplicated — a test (`every strategy applicableGoals field matches its actual GOALS membership`) locks this in.
- Shared constants: `CONTENT_VERSION`, `LAST_REVIEWED`, `MAX_COMPARISON_STRATEGIES`, `COMPARISON_LIMIT_MESSAGE`, `EDUCATIONAL_DISCLAIMER`.
- This file has **zero imports** — confirmed by a dedicated test that reads its own source and asserts no `import` lines exist, which structurally guarantees it cannot be coupled to any other part of the app, recommendation-related or otherwise.

The page (`app/help/strategies/page.tsx`) is a thin, purely presentational consumer: no strategy-specific text, numbers, or logic live in the component — every card, detail section, and comparison row is generated by mapping over `STRATEGIES`/`GOALS`.

## 7. Accuracy refinements incorporated

- Bull Call Spread `timeDecay` explicitly says decay "depends on the stock price relative to the strikes and the time remaining" (exact required framing).
- Bull Put Spread, Bear Call Spread, and Iron Condor `timeDecay` all explicitly note "theta behavior can change as the underlying moves through the strikes."
- No strategy's `expirationBreakeven`/`assignmentExercise` text guarantees expiration or non-assignment exactly at a strike — tested by asserting none of the 8 entries contain phrasing like "will expire exactly at" or "guaranteed to land exactly at."
- Early assignment, dividend risk, expiration risk, after-hours/pin risk, and (where relevant) protective-long-leg handling are covered via shared, single-sourced caveat strings applied per strategy based on actual applicability (e.g., dividend risk only on strategies with a short call leg; pin risk on Iron Condor/Covered Call/CSP/LEAPS where a stock can settle very near a strike).
- PMCC has its own dedicated long-leg caveat (`PMCC_LONG_LEG_CAVEAT`) rather than reusing the generic "protective leg" wording, since its long call is the core stock-substitute leg, not a pure hedge.
- PMCC's `maxLossExplanation` and `assignmentExercise` both explicitly state that assignment or mishandling can produce a realized result different from the initial net debit.
- Every strategy's `caveats` includes the buying-power disclosure (broker treatment may differ from the simplified capital examples shown).
- "Defined risk does not necessarily mean small risk" is retained on every strategy actually labeled defined-risk (PMCC, both vertical spread types, Iron Condor, Long LEAPS Call) — intentionally omitted from Covered Call and Cash-Secured Put, which are labeled as large/uncapped-to-zero risk rather than "defined risk," so the phrase wouldn't apply to them.

## 8. Accessibility behavior

- **Goal picker**: native `<fieldset>`/`<legend>` + 6 `<input type="radio" name="strategy-goal">`, each wrapped in a `<label>`. Selected state is the real DOM `checked` property (`getByRole('radio')` + `toBeChecked()` in tests) — no custom ARIA needed; keyboard support (Tab, Arrow keys, Space) is native browser behavior.
- **Comparison checkboxes**: native `<input type="checkbox">` per card and again in the detail view, each with a distinct `aria-label` ("Add {strategy} to comparison"). Checked state is real, programmatically determinable state.
- **Disclosure controls**: every detail subsection (position legs, examples, max profit/loss, time decay, volatility, assignment/exercise, use/avoid, beginner misunderstanding, caveats) is a native `<details>`/`<summary>` — expanded/collapsed state is exposed natively (the `open` attribute), with built-in keyboard toggling (Enter/Space on the summary).
- **Focus management**: opening a strategy detail moves focus to its `<h2>` heading (`tabIndex={-1}` + `.focus()` in a `useEffect` keyed on the selected strategy id). Returning to results restores focus to the exact card button that opened the detail (tracked via a ref to the opener's id, `document.getElementById(...).focus()` after the DOM updates).
- **Comparison-limit feedback**: a persistent `role="status" aria-live="polite"` region announces `COMPARISON_LIMIT_MESSAGE` verbatim the moment a 4th selection is attempted; it's also visibly rendered (not `sr-only`) whenever populated, and reset to empty (and visually hidden again) on the next successful selection change.
- **No color-only risk signaling**: every mechanical risk label is rendered as explicit text (`RiskBadge`) alongside a `⚠` glyph — color/border tinting is supplementary, never the only signal. Buy/Sell/Own leg badges are text-labeled ("BUY"/"SELL"/"OWN"), not color-coded alone.
- **Keyboard-only access**: every interactive control is a real `<button>`, `<input type="radio">`, or `<input type="checkbox">` — none of the interactions (opening a detail, toggling comparison, expanding a disclosure, removing/clearing comparison) depend on hover; all are click/Enter/Space-activatable and tab-reachable in document order.

## 9. Responsive behavior

- Card grid: `grid-cols-1` (mobile) → `sm:grid-cols-2` → `lg:grid-cols-3`.
- Goal picker: `grid-cols-1` (mobile) → `sm:grid-cols-2`.

## 12. Deviations from the approved design, and why

- **No explicit 7th "reset" radio in the goal group.** The approved design specifies exactly six goal choices. Rather than adding an implicit 7th "All strategies" radio option (which would exceed "six goal choices" as stated), the default (no goal selected) state shows all 8 strategies unfiltered, and a separate, clearly-labeled "Show all strategies" button (outside the radiogroup) clears the selection back to that default. This keeps the radiogroup at exactly six options while still satisfying "provide a clear return to filtered results" and letting users browse the complete reference without being forced through a goal.
- **Detail subsections default to expanded (`<details open>`).** The ticket requires a "complete expandable reference for every strategy." Defaulting every subsection open shows the complete reference immediately on opening a strategy (nothing hidden by default), while still giving users the ability to collapse sections they don't need — satisfying "expandable" without requiring an extra click to see the actual content.
- **No URL/query-param deep-linking to a specific goal or strategy.** The ticket's navigation requirements (preserve goal across detail views, clear return to results, preserve comparison) are all satisfiable — and were implemented — as in-page component state; the ticket did not explicitly request shareable/bookmarkable URLs for a specific goal or strategy, and the existing codebase's own tab-state patterns (e.g., `app/portfolio/page.tsx`) do not two-way-sync state to the URL either, so this keeps the new page consistent with that convention. This can be added later without any content-model change if desired.
- **`app/help/page.tsx`'s pre-existing, locally-duplicated `THEMES`/`getSavedTheme` were left as-is.** They are a pre-existing inconsistency (that page predates `lib/theme.ts`'s introduction elsewhere) unrelated to this ticket's scope; migrating them was not requested and risked unrelated visual/behavioral changes to the existing Help page, so only the new entry-point card was added using that file's existing local theme object for visual consistency with the rest of that page.

No other deviations. Every explicitly-required experience item (1–12), navigation/state behavior, trading-content correction, accuracy refinement, and accessibility requirement in the ticket was implemented as specified.
