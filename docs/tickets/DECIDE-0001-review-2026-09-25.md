# DECIDE-0001 review (2026-09-25)

**Reviewed:** `docs/tickets/DECIDE-0001-decisive-position-recommendations.md` as merged in `d311fd8`.
**Reviewer:** the working session, applying the Ian, Alan, Quinn, Paul and Diane lenses inline. This is not an independent-agent review. Because the ticket changes risk logic, an independent second opinion is recommended after the ticket is revised.
**Verdict:** **Do not build yet.** The design shape is sound (pure rules, code decides, AI explains, everything logged). Three findings change what would be built and must be settled first. Three more are serious but do not change the design.

## Blocking

### 1. The stop is defined differently from production (Ian, Alan)

The ticket says: stop when `mark ≥ 3·C`, "a loss of 2× credit".

The code says otherwise:

- `lib/portfolio/stopLossPolicy.ts:184`: `DEFAULT_ENTRY_STOP_MULTIPLE = 2`, and `buildOriginalCreditDefaultPolicy` sets `triggerPrice = credit × 2`. That is a mark of 2× credit, a loss of 1× credit.
- `lib/portfolio-intelligence/policies/defaults.ts:16`: `materialLossPct: -100` (a loss of 100% of the credit, the same point).
- `docs/ROADMAP.md` ES-0003: Stop Limit "trigger 2x credit".

Adopting the ticket as written would silently loosen every stop by one full credit. **Decision needed:** keep production's convention (mark ≥ 2·C) and rewrite the ticket and Alan's fixtures, or make a deliberate, recorded decision to loosen it (and change the stop-loss wiring to match). Recommendation: keep production's. The phrase "2x credit loss stop" in CLAUDE.md is ambiguous and should be corrected to say which.

### 2. It ignores position intent (Ian)

POSITION-INTENT-0001 (built 2026-09-25) stores Income / Acquire / Wheel for lone short puts and calls. In this ticket a CSP or CC gets `CLOSE_STOP` (rule 2) and `CLOSE_BROKEN` (rule 3) whatever its intent.

Dean's stated position (2026-09-25): a CSP has an Acquire or a Wheel aspect, so a strong recommended action does not make sense for it. The existing recommendation code already follows this for Acquire and Wheel (`lib/portfolio-data/acquisition.ts:2314`: hold for assignment, no breach or stop exits).

The riskiest case is the CC rule "close both the call and the shares": it recommends selling the shares, and it ignores whether the shares are held as Hold or Wheel (stock intent now exists).

**Required change:** add an intent branch. For Acquire and Wheel, CSP and CC return `ACCEPT_ASSIGNMENT` or `HOLD` with the context shown, never `CLOSE_STOP` or `CLOSE_BROKEN`. Ian decides whether a hard loss limit still applies to them (he did not rule on this). The broken-stock signal may still be shown as information.

### 3. It runs against Dean's report on Cut Losses (Ian, Paul)

Dean reported that a loud "Cut Losses" led to panic closes on positions that later recovered. The Trade Log analysis (CUT-LOSSES-REVIEW-0001) found 21 of 28 losses were closed before reaching 2× credit and only one position was held near expiry. Ian's ruling: soften presentation and capture data now; no scoring change until outcome data exists.

This ticket makes recommendations more forceful and more certain. It should not start ahead of CUT-LOSSES-REVIEW-0001, and it must require the calm presentation (state the reasons, the flip conditions and what the position needs, not a red command). Paul: sequence it behind that ticket, or record Dean's explicit decision to proceed.

## Serious

### 4. The data the signals need does not exist (Alan, Quinn)

- **Trend break** needs 201 daily bars. `app/api/chart/route.ts:14` requests `range=6mo` (about 125 bars), so the rule could never fire. It needs at least a 1-year range.
- **Support break** needs volume. The chart route builds bars with only `t, o, h, l, c` (line 51); there is no `v`. The route would have to return volume.
- The chart data source is Yahoo, and the ticket says nothing about its adjusted-versus-unadjusted closes; Alan flagged this for RSI-TURN-0001 too.

### 5. Support at entry does not exist for current positions (Quinn)

`S` is "frozen when the position opens and stored in the entry record". Positions opened before 2026-09-25 have no entry snapshot (Trade Log CSV: the Score, Entry State and Entry Overrides columns are empty on all 65 rows). Every existing position would show this signal as "not evaluated". Decide: backfill from history at first evaluation (computed from bars before the entry date, labeled as reconstructed) or accept NE for old positions.

### 6. It duplicates the log that already exists (Quinn, Paul)

`lib/decision-review` (PI-0008C Decision Outcome Tracking) already has a `DecisionReview` with a trader-action vocabulary and outcome status. Dean's console query on 2026-09-25 showed **0 stored reviews**, so nothing is writing to it. DECIDE-0001D should extend or replace that module on purpose, and first find out why nothing writes reviews.

## What is good and should be kept

- Pure, deterministic evaluators with explicit inputs and a property test.
- `BLOCKED` is never `HOLD`, and confidence is null only when blocked.
- The AI cannot change the action; a server-side exact-match check discards a mismatch.
- The 21-DTE exception for CSP and CC (matches the CLAUDE.md change and the portfolio prompt).
- "Winners never roll", the fee-aware qualifying roll, and the wide-quote two-reading stop.
- Golden fixtures at every threshold boundary.
